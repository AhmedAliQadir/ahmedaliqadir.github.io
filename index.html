04 / Design

I design the thing before I build it

Interfaces don't survive contact with a compliance audit unless someone has thought about them first. These are the design artefacts behind the systems above — written, not improvised.

This site's design system

The page you are reading is the demonstration. One accent doing accent work, brass confined to a single job, two radii, two loaded families, a 1.25 type scale and a 65ch measure — all of it declared once as tokens and consumed everywhere, rather than decided per component.

Every colour pair is measured, not eyeballed: body text sits at 17.28:1 on the night surface and 16.29:1 on paper, the violet accent at 9.48:1, and interactive borders clear the 3:1 bar for non-text UI. No status anywhere on this site is carried by colour alone — the active nav item is violet and underlined, for the same reason.

Tokens — W3C DTCG JSON → Tokens — Tailwind → Tokens — CSS custom properties →

AccomPro design system

A written design specification that precedes the code: a Material Design 3–derived approach chosen deliberately for data-dense enterprise screens, with a documented light and dark palette in HSL, a nine-step type scale, spacing primitives and component patterns for tables, modals and multi-step forms.

Four stated principles govern it — information hierarchy, workflow efficiency, trust and professionalism, and scalable complexity — and every subsequent screen is checked against them.

Shipped product — AccomPro

Tourista motion & component library

A shared motion module defining easings and animation variants, plus nine reusable animated components — Aurora, Marquee, TextReveal, MagneticButton, Spotlight, BentoGrid, CountUp, Skeleton and ScrollProgress — so that every page inherits the same behaviour instead of reinventing it.

The whole system respects prefers-reduced-motion: the motion is a layer, never a dependency.

Shipped product — Tourista

Onboarding wizard pattern

An eleven-step resident onboarding flow documented as a reusable interaction pattern — autosave, per-step validation, resumable progress and error recovery — written up so the same pattern can be applied to the next long form rather than redesigned from scratch.

Shipped product — AccomPro

Wireframes, prototypes and the pre-redesign/redesign comparison from my Glasgow Caledonian University design work are being prepared for publication here. They are dated from source records rather than from file timestamps, so they go up when the dates are confirmed — not before.
