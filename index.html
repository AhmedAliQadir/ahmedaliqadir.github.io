01 — About & now

I start with the work, not the code.

Most automation fails because it's built around a tool rather than the business. I map how the work really happens first — then decide what to automate.

I'm an AI automation consultant. I help UK businesses find the manual, repetitive work that eats their week — enquiries, bookings, data entry, follow-ups, reporting — and replace it with AI agents and automations that fit how they already operate.

I build with Claude and the Model Context Protocol, so agents work with the systems a business already has rather than replacing them. I can write the code myself — TypeScript, Python, React — but the code is the means, not the point. Every build is documented and handed over, so the team can run it without me.

Before founding Orbixio Ltd I ran first-line incident management in a 24/7 telecom Network Operations Centre and, as an IT analyst, redesigned onboarding and access workflows. That's where I learned that a process only improves when the people who run it can see how it works.

03 — How I work

Mapped. Built. Handed over.

The same four steps on every engagement. No black boxes — your team can see how it works and run it without me.

  1. 01

    Map

    I sit with the people doing the work and map how it really runs today — every hand-off, spreadsheet and copy-paste — before anything is automated.

  2. 02

    Design

    We agree what an agent should handle, what stays with a person, and where a human approves before anything leaves the business.

  3. 03

    Build

    I build with Claude, the Model Context Protocol and the tools you already use, so nothing has to be ripped out to make it work.

  4. 04

    Document & hand over

    Every build ships with plain-English documentation and a handover, so your team owns it — and can change it.

04 — Design

I design it before I build it.

Interfaces don't survive a compliance audit — or a client sign-off — unless someone thought about them first.

Figma · Smooth Vault Moves

Three logos, one file, zero guesswork.

Three first-round directions for a removals brand, each drawn as components with light, dark and icon versions down to 32px — so the client judged them where they'd actually live, not on a blank square.

  1. Door to Door — one route forms the S, from your door to your new one.
  2. Vault Box — a moving box with a safe dial: removals and storage in one mark.
  3. Sorted — S✓M, the V turned into an orange tick, built for van sides.

A refined "Vault S" mark from round two won and is live on the client's site ↗.

This site's design system

One accent doing accent work, one yellow highlighter for play, two loaded families and tracking that tightens as type grows — declared once as tokens. Every colour pair is measured, and no state is carried by colour alone.

AccomPro design system

A written specification that precedes the code: Material Design 3–derived for data-dense screens, a documented light and dark palette, a nine-step type scale and patterns for tables, modals and multi-step forms.

Tourista motion library
